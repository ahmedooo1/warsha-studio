# بنية «ورشة العرض»

## الملفات

| الملف | المحتوى |
|---|---|
| `index.html` | الواجهة والمشهد ثلاثي الأبعاد والتسعير والمستندات والتخزين، في صفحة واحدة |
| `js/fab.js` | محرك التصنيع: إعدادات الورشة، تجهيز القطع، اتجاه العرق، خصم الحواف، تقسيم القطع الطويلة، مخطط التقطيع على الألواح، فحص القائمة |
| `tests/fab.test.mjs` | اختبارات وحدة لمحرك التصنيع (Node، بلا متصفح) |
| `tests/syntax.test.mjs` | يتحقق أن سكربت الصفحة يُترجَم دون أخطاء |
| `tests/e2e.mjs` | اختبار شامل في متصفح حقيقي على سبعة مشاريع واقعية، وعلى عرض الهاتف |
| `docs/` | هذا الملف وتقرير التدقيق |

## طبقات `index.html` بالترتيب

1. **الكتالوج والبيانات**: الخامات، الوحدات `UNIT`، القطع المستقلة `ITEM`، القطع المخصصة، القيم الافتراضية `DEFAULT`، وتنظيف البيانات `sanitize` و`sanitizeItems` و`sanitizeUnits`.
2. **التوزيع**: `runsOf` و`layoutRun` يحوّلان قوائم الوحدات إلى مواضع على الجدران، و`autoUnits` و`autoItems` يولّدان التوزيع التلقائي لكل غرفة.
3. **المحرك ثلاثي الأبعاد**: الخامات المولّدة، المواد، بُناة الوحدات والقطع، `buildRoom` و`build`، الإضاءة، الكاميرا، طبقة المقاسات.
4. **التحرير**: التحديد، السحب الحر والالتصاق والتركيب (`poseAt`)، تحرير وحدات الجدار، لوحة الخصائص، التراجع والإعادة.
5. **الحساب**: `saleLines` (سعر البيع)، `cutList` (قائمة التقطيع، تستدعي `js/fab.js`)، `costOf` (التكلفة).
6. **المستندات**: رسم A4 على canvas، كاتب PDF صغير، عرض السعر، ورقة الورشة، CSV، المخطط من الأعلى، مخطط الألواح.
7. **المشاريع**: الحفظ لكل زبون، الحفظ التلقائي للعمل الجاري، النسخ البديلة، التصدير والاستيراد والنسخة الاحتياطية، المشاريع التجريبية، وضع العرض للزبون.

## نموذج البيانات

- التصميم `cfg`: الغرفة والشكل ومقاسات الجدران والخامات، و`units` (وحدات كل جدار في مستويين `b` و`u`)، و`items` (القطع الحرة)، و`extras` و`disc` (بنود إضافية وخصم).
- القطعة الحرة: `t` النوع، `w` العرض، `x` و`z` مركزها بالسنتيمتر من الجدار الأيسر والجدار الخلفي، `r` الدوران بالدرجات، `y` الرفع اليدوي، `sy` الرفع الناتج عن التركيب، و`h` و`d` للقطع المخصصة، و`o` الخيارات.
- كل ما يُقرأ من التخزين أو من ملف مستورد يمر على `sanitize`، فلا يدخل مقاس خارج الحدود ولا نوع غير معروف.

## التخزين

| المفتاح | المحتوى |
|---|---|
| `wr_designs` | تصاميم الزبائن (خارج Claude) |
| `wr_draft` | العمل الجاري، يُحفظ تلقائياً بعد كل تعديل |
| `wr_prices` | أسعار الورشة وهويتها وشعارها |
| `wr_fab` | إعدادات التصنيع |

داخل Claude تُحفظ التصاميم في قاعدة بيانات الصفحة بدل `wr_designs`.

## لماذا بقيت الصفحة ملفاً واحداً

الأداة تعمل بفتح الملف مباشرة، وتُنشر صفحة واحدة. فصل كل الطبقات يحتاج أداة بناء أو عدة ملفات تُحمَّل بالترتيب، وكلاهما يغيّر طريقة النشر. لذلك فُصلت الطبقة الأخطر أولاً، وهي حسابات التصنيع، في ملف مستقل مختبَر. التوصية للمرحلة القادمة: نقل الكتالوج ثم التسعير ثم المستندات إلى ملفات `js/` بالطريقة نفسها، طبقة في كل مرة، مع تشغيل `npm test` و`npm run test:e2e` بعد كل خطوة.

## الاختبارات

```bash
npm i            # three@0.147.0 للاختبار الشامل
npm test         # اختبارات محرك التصنيع وترجمة السكربت
npm run test:e2e # سبعة مشاريع في متصفح حقيقي، والهاتف
```

الاختبار الشامل يحتاج Playwright ومتصفح Chromium مثبتين.
