# ورشة العرض كمنصة للورشات: التحليل والخطة

هذا الملف هو المرجع لتحويل «ورشة العرض» من صفحة واحدة تعمل على جهاز النجار إلى منصة تُباع للورشات باشتراك. القاعدة الأولى فيه: **لا تضيع أي ميزة موجودة**.

## 1. الوضع الحالي

صفحة واحدة (`index.html` نحو 480 كيلوبايت، مع `js/fab.js` و`js/i18n.js` و`assets/`) تعمل في المتصفح بلا خادم. كل البيانات في `localStorage` على الجهاز، أو في قاعدة بيانات الصفحة حين تُفتح داخل Claude. المساعد الذكي «طلب الزبون» يعمل فقط داخل Claude.

نقاط القوة: المحرر ثلاثي الأبعاد، قائمة القص، التسعير، المستندات، اللغات الثلاث، وفحوص آلية (115 فحصاً في متصفح حقيقي).

ما يمنع البيع:

| المشكلة | الأثر على الورشة | الحل في المنصة |
|---|---|---|
| الحفظ على الجهاز فقط | ضياع مشاريع الزبائن عند مسح المتصفح أو تغيير الهاتف، ولا عمل مشترك | حسابات وورشات وحفظ على خادم PostgreSQL، مع إبقاء الحفظ المحلي |
| لا حسابات ولا ترخيص | أي أحد يستعمل الأداة مجاناً | تسجيل ورشة، تفعيل يدوي بمدة ترخيص، لوحة إدارة لصاحب المنصة |
| المساعد يعمل داخل Claude فقط | تختفي الميزة خارج Claude | نقطة في الخادم تستدعي Claude API بمفتاح المنصة |
| عرض السعر بلا بيانات قانونية فرنسية | الـ devis غير مكتمل قانونياً | حقل «البيانات القانونية» (SIRET، رقم الضريبة، RCS…) وترقيم متسلسل للعروض لكل ورشة |
| لا رابط للزبون | الورشة ترسل صوراً فقط | رابط خاص يفتح التصميم ثلاثي الأبعاد للزبون، مع موافقته على العرض |
| لا متابعة للطلبات | دفتر ورقي بجانب الأداة | مراحل لكل مشروع: مسودة، عرض مرسل، موافقة، تصنيع، تركيب |
| بيانات الزبائن بلا سياسة | خطر RGPD | تصدير وحذف بيانات زبون، سجل عمليات، صفحات قانونية |

## 2. جرد الميزات التي يجب أن تبقى كلها

المحرر يُدمج في المنصة **كما هو**، فكل ما يلي يبقى بالكود نفسه، ويُفحص بالفحوص نفسها بعد كل تغيير:

- **الغرف**: 11 نوعاً، مخطط I وL وU، الجدران الأربعة بثلاثة مستويات (أرض، جدار، فوق العلوية)، النوافذ والأبواب.
- **الوحدات**: كل أنواع المطبخ والخزائن الطويلة والمنخفضة والديكور، أعمدة بارتفاع قابل للتعديل، الشفاط بأشكاله الأربعة ومدخنته.
- **التصميم الحر**: مكتبة القطع بالسحب والإفلات، الخزانة المخصصة لوحة لوحة، البار، اللوح الحر، القوالب وطاولات التلفزيون، التكديس، الزوايا المدوّرة والمائلة من فوق ومن الأمام، منع التداخل، حدود الغرفة، المكان الفارغ، النسخ، الشريط المتحرك، اختصارات لوحة المفاتيح، التراجع والإعادة.
- **العرض**: ثلاث جودات، خامات حقيقية، HDR، النهار والمساء، التصوير الواقعي، صور حتى 4K وA4، وضع العرض للزبون، الجولة، فتح الأبواب، مقارنة البدائل.
- **الورشة**: قائمة القص بالمليمتر، مخطط الألواح، الحواف والإكسسوارات، إعدادات التصنيع، ملاحظات الورشة، التكلفة والربح، البنود الإضافية والخصم، عرض السعر PDF، ورقة الورشة PDF، CSV.
- **الزبائن**: الحفظ مع الهاتف والملاحظات والصورة، الحفظ التلقائي، النسخ البديلة، تصدير مشروع، نسخة احتياطية كاملة، الاستيراد، المشاريع التجريبية، فحص الجهاز.
- **الهوية**: الاسم، الشعار، الهاتف، البريد، العنوان، لون الهوية، صلاحية العرض، الشروط.
- **اللغات**: العربية والفرنسية والتركية، والمستندات بها.
- **المساعد**: تحويل طلب الزبون (نص أو صورة) إلى تصميم.

## 3. القرار المعماري

**المحرر لا يُعاد كتابته.** يبقى ملفاً واحداً في جذر المستودع، وهو نفسه المنشور على GitHub Pages ويعمل وحده. المنصة تقدّمه في `/studio/` وتضيف ملفاً واحداً `cloud.js` يُحمَّل قبله، يربطه بالخادم عبر نقاط توصيل صغيرة في المحرر لا تعمل إلا إذا وُجد `window.WarshaCloud`:

| نقطة التوصيل في المحرر | ما تفعله في المنصة | دون المنصة |
|---|---|---|
| `store.init` يقبل قاعدة بيانات خارجية | قائمة التصاميم وحفظها وحذفها عبر الخادم | `localStorage` كما الآن |
| `lsSet` لـ `wr_prices` و`wr_fab` | أسعار الورشة وإعدادات التصنيع وهويتها تُحفظ في حساب الورشة | الجهاز |
| `WarshaHost.openDesign/applySettings/clientView` | فتح مشروع من رابط، تطبيق إعدادات الورشة، عرض الزبون للقراءة فقط | لا شيء |
| رقم عرض السعر | رقم متسلسل من الخادم `DEV-2026-0001` مع حفظ مجاميع العرض | الرقم المحلي الحالي |
| المساعد `sample` | الخادم يستدعي Claude API | داخل Claude كما الآن |
| حقل البيانات القانونية | من إعدادات الورشة | يُكتب يدوياً، وهو ميزة جديدة للنسخة المحلية أيضاً |

بعد ثبات المنصة يُقسَّم المحرر تدريجياً إلى وحدات (الهندسة، قائمة القص، المستندات، الواجهة)، كل خطوة مع الفحوص الـ115 نفسها، ولا خطوة تُدمج قبل أن تنجح كلها.

## 4. التقنيات

| الجزء | التقنية |
|---|---|
| الخادم | NestJS، TypeScript |
| قاعدة البيانات | PostgreSQL 16، Prisma |
| الواجهة | Nuxt (Vue 3)، بالعربية والفرنسية والتركية وبنفس هوية المحرر |
| المحرر | الملفات الحالية دون إعادة كتابة، three.js r147 |
| الجلسات | رمز عشوائي في كوكي `httpOnly` و`SameSite=Lax`، مخزّن مشفّراً (SHA-256) في جدول الجلسات، يُلغى عند الخروج |
| كلمات المرور | bcrypt |
| التشغيل | Docker Compose (قاعدة البيانات، الخادم، الواجهة)، وتشغيل محلي دون Docker |
| الفحوص | فحوص الخادم على PostgreSQL حقيقية، فحص المسار كاملاً في المتصفح، وفحوص المحرر الحالية |

## 5. قاعدة البيانات

- **Workshop**: الاسم، الحالة (بانتظار التفعيل، مفعّلة، موقوفة)، الخطة، نهاية الترخيص، البيانات القانونية (الاسم القانوني، SIRET، رقم الضريبة، العنوان، الهاتف، البريد، الموقع)، الشعار، إعدادات المحرر (`prices`، `fab`) بصيغة JSON، عدّاد عروض الأسعار وبادئتها.
- **User**: البريد، كلمة المرور المشفّرة، الاسم، صاحب المنصة أو لا.
- **Membership**: مستخدم في ورشة بدور «مالك» أو «موظف».
- **Session**: جلسات الدخول.
- **Client**: زبون الورشة: الاسم، الهاتف، البريد، العنوان، ملاحظة.
- **Project**: تصميم المحرر بحقوله نفسها (الاسم، الهاتف، الملاحظة، `cfg`، الصورة، النسخة البديلة)، مع الزبون والمرحلة.
- **ProjectVersion**: آخر 30 نسخة محفوظة لكل مشروع، للرجوع إليها.
- **Quote**: رقم متسلسل لكل ورشة، المجاميع، العملة، الصلاحية، الحالة، وبيانات موافقة الزبون (الاسم، الوقت).
- **ShareLink**: رمز عشوائي طويل، المشروع، العرض، تاريخ الانتهاء، الإلغاء، عدد المشاهدات.
- **AuditLog**: من فعل ماذا ومتى.

كل استعلام مقيّد بورشة المستخدم. لا يرى أي مستخدم بيانات ورشة أخرى، وهذا مفحوص آلياً.

## 6. الأمان والقانون

- عزل الورشات في كل نقطة من الخادم، وفحص آلي لمحاولة قراءة مشروع ورشة أخرى.
- حدود لعدد المحاولات على الدخول والتسجيل والمساعد.
- رؤوس أمان (`helmet`)، التحقق من كل مدخل (`class-validator`)، حجم أقصى للطلبات.
- الورشة غير المفعّلة أو المنتهي ترخيصها: تقرأ وتصدّر بياناتها، ولا تحفظ تعديلات جديدة. بياناتها لا تُحذف.
- RGPD: تصدير كل بيانات زبون، حذفه مع مشاريعه، تصدير كل بيانات الورشة، سجل العمليات.
- صفحات «Mentions légales» و«CGV» و«Politique de confidentialité» **قوالب** يجب أن يراجعها محامٍ أو محاسب قبل البيع. المنصة لا تدّعي أنها مطابقة قانونياً دون هذه المراجعة.
- عرض السعر يطبع البيانات القانونية للورشة ورقمه المتسلسل. البيانات الإلزامية للـ devis في فرنسا تُراجع مع محاسب.

## 7. المراحل

**المرحلة 1 (يُبنى الآن على فرع `saas`)**
1. هيكل المستودع: `apps/api` و`apps/web`، والمحرر في الجذر كما هو.
2. الخادم: الحسابات، الورشات، التفعيل، الزبائن، المشاريع والنسخ، المراحل، روابط الزبون، عروض الأسعار، الإعدادات، المساعد، RGPD، السجل.
3. نقاط التوصيل في المحرر و`cloud.js`.
4. الواجهة: التسجيل والدخول، لوحة الورشة، الزبائن، المشاريع، الإعدادات القانونية، الأعضاء، لوحة الإدارة، صفحة الزبون.
5. Docker Compose والتشغيل المحلي والفحوص.

**المرحلة 2 (بعد تجربة صديقك على مشاريع حقيقية)**
- تصحيح قائمة القص حسب ملاحظات النجار.
- النشر على خادم (OVH أو Hetzner) بنطاق خاص وشهادة HTTPS ونسخ احتياطي يومي لقاعدة البيانات.
- Stripe للاشتراكات، تُربط بحقل الترخيص الموجود.
- البريد: تأكيد الحساب، استعادة كلمة المرور، إرسال رابط العرض للزبون.

**المرحلة 3 (ما يرفع القيمة)**
- غرف غير مستطيلة: أعمدة، جسور، زوايا غير قائمة، تمديدات.
- كتالوج خامات وإكسسوارات الورشة بأسعارها (Blum، Hettich…).
- تصدير القص لبرامج التقطيع.
- عمل دون إنترنت (PWA).
- تقسيم المحرر إلى وحدات تدريجياً.

## 8. معيار «جاهز للبيع»

- كل فحوص المحرر وفحوص المنصة ناجحة.
- 3 إلى 5 مشاريع حقيقية نُفّذت بقائمة القص وراجعها نجار.
- تجربة على هاتف Android حقيقي.
- المراجعة القانونية للصفحات وعرض السعر.
- خامات منزّلة من مصادرها الرسمية.
- نسخ احتياطي آلي لقاعدة البيانات، ومراقبة للأخطاء.
